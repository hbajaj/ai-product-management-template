## Problem & user

RocketShip PMs need evidence-based prioritisation. Juno reads the strategy and the customer signal, ranks the backlog, and defends every call with a citation, inside limits a human set on purpose.

## 01 Context · Data Requirements

**Required sources, and exclusions**

Required sources

Uploaded interview/call transcripts in Transcript Input
Strategy documents uploaded as .txt or .md into Strategy Source
Jira/support ticket records exposed to Juno through read_tickets()
For production Juno: authorized Slack product/escalation channels, Jira projects, and Notion product/strategy pages

Deliberately excluded

Customer-facing email and Slack sending
Private Slack channels not explicitly authorized
HR, employee-performance, or unrelated company data
Deleted/archived tickets
Strategy inferred from model memory or hardcoded company context

Juno may only make strategic claims from strategy content actually loaded into the system.

**SLA of truth**

SLA of truth · how fresh must it be
Uploaded transcript/strategy: available to Juno immediately after successful parsing/indexing
Jira/ticket data: retrieve live at analysis time; target freshness <5 minutes
Slack/Notion in production: refresh on request or webhook/index update; target <5 minutes for high-priority signals
Each answer records source + retrieval timestamp

## 02 Tools · System Capabilities

**The verb list**

search_strategy(query) retrieves matching clauses and headings from the uploaded strategy document. Side effect: READ. Permission: AUTO.

read_tickets(filter) retrieves matching ticket records. Side effect: READ. Permission: AUTO.

draft_priority(insight_id, priority, rationale) creates a proposed priority for PM review. Side effect: DRAFT. Permission: AUTO.

write_roadmap(insight_id, priority) commits an approved priority to the roadmap state. Side effect: WRITE. Permission: CONFIRM.

**Deliberate omissions**

Deliberate omissions, and why

Juno deliberately has no tools for:

Sending Slack or email messages
Publishing customer-facing communication
Deleting or archiving tickets

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

Turn ceiling and escalation trigger

Maximum: 5 agent turns per request.

Juno stops earlier when:

The task is successfully completed
A WRITE action requires human confirmation
The same tool fails 3 consecutive times
Required evidence is unavailable and proceeding would require unsupported assumptions

At turn 5:

Return the best available result explicitly labeled “Turn limit reached.”

After 3 consecutive failures:

Stop immediately and explain what Juno attempted, what failed, and what a human should inspect.

No fourth retry.

**Latency and cost target**

Latency and cost target
p95 end-to-end latency: <8 seconds
Target model/tool cost: <$0.10 per normal prioritization task
Log all requests exceeding 8 seconds
Display cumulative token usage/cost in the Tool Trace

The optimization goal is not minimum model usage. It is:

PM time saved must substantially exceed AI latency and review cost.

## 05 Permissions · AI Risks & Mitigations

**The autonomy dial**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Justify the tiers

READ → AUTO

Blast radius is low and actions are reversible/non-mutating. Requiring confirmation every time Juno searches strategy or tickets would destroy the benefit of the agent.

DRAFT → AUTO

Juno can create a recommendation because nothing has changed in the system of record. The PM can edit or discard it at negligible cost.

WRITE → CONFIRM

Changing roadmap priority can affect engineering allocation, customer expectations, and executive decisions. The change may technically be reversible, but organizational consequences may not be.

Therefore:

Juno prepares the action; a human authorizes it.

SEND → BLOCKED

External communication can create customer commitments or reputational/legal consequences and is unnecessary for V1.

No send capability is exposed to the agent at all

## 06 Verification · AI Testing & Measurement

**The check before output ships**

The check that runs before output ships

Before Juno surfaces a priority recommendation, run a deterministic verification pass checking:

1. Evidence grounding
Every strategic claim must map to a search_strategy() result with a heading and clause.

2. Source integrity
Ticket claims must exist in actual read_tickets() results.

3. Unsupported-claim check
No company pillar, customer impact, ticket count, or strategic assertion may come solely from model memory.

4. Recommendation completeness
Priority recommendation must contain:

Insight
Priority
Rationale
Evidence/source clause
Confidence or uncertainty where applicable

5. Permission check
Any WRITE action must have recorded human approval before execution.

6. Trace completeness
Every attempted tool call, including failures, must appear in the Tool Trace.

Shipping bar

For consequential recommendations:

100% of strategic claims must be source-grounded and every WRITE must have explicit human approval.

Those are hard gates, not aggregate accuracy targets.

**Failure behaviour**

If verification fails:

Juno does not present the unsupported conclusion as a normal recommendation.

Instead it shows:

Needs Human Review
I could not verify this recommendation because [missing/failed evidence].

It should preserve:

available evidence
missing information
failed tool call
draft conclusion, clearly marked as unverified
suggested human next step
