## Goal

Reduce PM decision latency and prioritization risk by having Juno synthesize cross-channel evidence, draft an evidence-backed priority recommendation, and return control to the PM before any roadmap-changing action is committed.

**Primary actor:** Planner + Executor agents

## Trigger

Juno activates when a new transcript, ticket batch, or strategy document is uploaded and at least one actionable product issue is detected with supporting evidence from the input.

## Steps & tools

**Pattern:** Planner-Executor (multi-agent, parallel)

**Schemas**

**Memory (in or out of scope)**

- **Episodic:**  Episodic memory: In-scope for the current run only. Stores the sequence of planner decisions, tool calls, tool results, failures, PM approve/reject actions, and the current draft recommendation. Lifetime: until the run ends.

- **Semantic:** Retrieved, not persisted in working memory: Strategy documents and ticket records stay in their source systems and are fetched again through search_strategy() and read_tickets() when needed. This keeps Juno from relying on stale copied context.
- **Working:** Working memory: Holds only what Juno needs to complete the current task, such as the active insight, retrieved strategy clauses, matching ticket evidence, current priority hypothesis, and pending confirmation state.
- **External:** Slack thread API (read), RocketShip Strategy KB (read), Salesforce ARR lookup (read), #pm-daily channel (write), Jira (write, stub creation only).

## Human-in-the-loop

The Planner Agent decides which evidence and tools are needed, and the Executor Agent carries out READ and DRAFT actions automatically. Control passes back to the PM when Juno proposes a WRITE action such as changing roadmap priority, when required evidence is missing, or when the loop hits its failure/turn limit.

## Success & failure

- **Done when:** Stop conditions:

Success: Evidence-backed priority draft is complete and ready for PM review.
Human escalation: Juno reaches a WRITE action such as write_roadmap() and pauses for explicit PM approval or rejection.
Failure: The same tool fails 3 consecutive times. Juno stops and returns what it attempted, what failed, and what the PM should check.
Turn limit: Juno reaches the 5-turn maximum and returns its best current answer labeled “Turn limit reached.”
Insufficient evidence: Required strategy or ticket evidence is missing, so Juno stops before making an unsupported recommendation and marks it “Needs Human Review.”
- **Fails safe when:** Agent can READ Slack #escalations + Strategy KB + Salesforce ARR. Agent can WRITE to #pm-daily and create Jira stubs. Agent CANNOT edit Salesforce records, edit Jira tickets after creation, or post outside #pm-daily.
