## Autonomy level

Juno may read evidence, compare signals, and draft priority recommendations automatically, but it cannot commit a roadmap change on its own.

## Controls

- **Kill switch:** Set max_steps = 5.

Juno aborts and hands control back when:

the task is successfully completed,
the same tool fails 3 consecutive times,
required evidence is missing or cannot be verified,
a WRITE action requires PM approval,
or step 5 is reached.

At the limit, Juno returns its best current result labeled “Turn limit reached” instead of continuing.
- **Rate / cost caps:** Use structured JSON with explicit success/failure fields so the Planner reasons over observations, not free-form prose.

search_strategy() → { success, matches: [{ heading, clause }], source_name, retrieved_at, error }
read_tickets() → { success, tickets: [{ id, title, status, severity, customer_impact }], count, retrieved_at, error }
draft_priority() → { success, insight_id, proposed_priority, rationale, draft_id, error }
write_roadmap() → { success, insight_id, committed_priority, approved_by, timestamp, error }

Rule: failed or empty results return explicit success: false or matches/tickets: []; tools never invent fallback content.
- **Escalate-on-stuck:** allback Protocols

Missing evidence: Stop the affected recommendation, label it “Needs Human Review,” and show exactly what source is missing.
Tool failure: Retry the same tool up to 3 consecutive times; on the third failure, stop and return what Juno attempted, what failed, and what the PM should check.
Turn limit: At 5 turns, stop and return the best current answer labeled “Turn limit reached.”
WRITE gate: Pause on write_roadmap() until the PM explicitly Approves or Rejects. Reject returns to the loop as feedback.
Low confidence: If confidence is <60%, do not auto-prioritize; hand control back to the PM.
Source unreachable: Continue only with verified available evidence, lower confidence, and never invent missing facts.

## Monitoring

**Confidence thresholds (map to actions):**

≥ 80% confidence: Juno may proceed with READ/DRAFT actions automatically and present the recommendation normally.
60–79% confidence: Juno may draft, but flags the result “Review Recommended” and highlights the uncertain evidence.
< 60% confidence: Juno stops autonomous prioritization and hands back to the PM as “Needs Human Review.”
Missing required source evidence: Confidence is treated as N/A, not estimated. No strategic claim is made.
Any WRITE action: Always requires PM confirmation, regardless of confidence.

**Checkpoints:**

Checkpoints

Human intervention is required when any red-zone trigger occurs:

WRITE action proposed: Any write_roadmap() call requires explicit PM approval.
Low confidence: <60% confidence triggers Needs Human Review.
Conflicting evidence: Strategy, tickets, or transcript signals materially disagree.
Missing critical context: Customer impact, severity, or strategic support cannot be verified.
High-impact prioritization: A proposed P0/P1 or roadmap change could materially affect customer commitments or engineering allocation.
Loop instability: Same tool fails 3 times or the agent reaches the 5-turn limit.

**North Star (re-read every loop):**

Prime directive: Reduce PM decision latency without sacrificing trust. Use only retrieved evidence, prioritize the highest-impact verified risk, make uncertainty explicit, and never commit a roadmap change without human approval.

## Permissions

search_strategy() → READ only from the currently loaded strategy document. Cannot modify, replace, or delete strategy content.
read_tickets() → READ only from the ticket fixture / Jira data source. Cannot update status, priority, assignment, or archive tickets.
draft_priority() → WRITE only to Juno’s draft state. Can create or update a proposed priority, but cannot change the roadmap system of record.
write_roadmap() → WRITE to roadmap state only after PM confirmation. Cannot send messages, delete records, or modify unrelated fields.
Session/agent memory → Juno may write temporary run state, tool results, trace entries, and approval decisions; it cannot overwrite source-of-truth systems.
No access to email/Slack sending, customer-facing publishing, ticket deletion, archival, or other destructive actions
